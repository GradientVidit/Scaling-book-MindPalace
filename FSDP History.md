## 1. Summed up Outline

| Generation                       | Main idea                               | What is distributed/sharded?                 | Primary trade-off                                                                                                                                                                          |
| -------------------------------- | --------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Traditional DDP**              | Replicate the model on every rank       | Nothing                                      | Simple, but high memory redundancy (full model, grad, and optimizer replica on each rank)                                                                                                 |
| **ZeRO-1**                       | Shard optimizer state                   | Optimizer states                             | ~4x memory reduction (FP16+Adam); **0% extra communication volume** relative to DDP                                                                                                       |
| **ZeRO-2**                       | Shard optimizer state + gradients       | Optimizer states + gradients                 | ~8x memory reduction; **0% extra communication volume** relative to DDP                                                                                                                    |
| **ZeRO-3**                       | Fully shard model state                 | Optimizer states + gradients + parameters    | Max memory reduction; **+50% communication volume overhead** (parameter AllGather in forward pass)                                                                                        |
| **FSDP1**                        | Native PyTorch fully sharded training   | Parameters + gradients + optimizer states    | Uses `FlatParameter`; flattens module parameters into 1D tensors, breaking parameter identity and hindering `torch.compile` & Tensor Parallelism composability                             |
| **FSDP2**                        | Per-parameter `DTensor` sharding          | Parameters + gradients + optimizer states    | Uses `fully_shard` and `DTensor`; preserves parameter identity, enabling seamless `torch.compile`, 2D/3D parallelism (`TP + FSDP2`), and FP8 communication                             |
| **HSDP**                         | Hierarchical sharding + replication     | Shards within node/group, replicas across nodes | Trades memory efficiency for network topology; reduces cross-node AllGather latency by replicating across nodes over IB/EFA and sharding over intra-node NVLink                           |
| **Multidimensional parallelism** | Combine multiple parallelism dimensions | FSDP2 + TP + PP + CP, etc.                    | Enables trillion-parameter model training (e.g. TorchTitan); increases scheduling and collective communication complexity                                                                  |

## 2. Detailed Outline

| Date | Event | Why it matters |
|---|---|---|
| **2018–2019** | **Pre-ZeRO Parallelism (Mesh TensorFlow, GPipe, Megatron-LM)** | **Precursor context:** Early solutions to model memory bottlenecks relied on Pipeline Parallelism (GPipe) and Tensor Parallelism (Mesh TensorFlow, Megatron-LM). While effective, they required intrusive code refactoring to split linear layers. Data Parallelism (DDP) remained simple but memory-bound. |
| **Oct 2019** | **ZeRO paper** | Published by Microsoft (Samyam Rajbhandari et al., SC '20). Introduces Zero Redundancy Optimizer to eliminate data-parallel memory redundancy. **ZeRO-1** shards optimizer states; **ZeRO-2** additionally shards gradients; **ZeRO-3** additionally shards parameters. Key theoretical insight: ZeRO-1 and ZeRO-2 achieve up to 8x memory reduction with **zero communication overhead penalty** compared to standard DDP. |
| **Feb 2020** | **DeepSpeed open-sourced** | Microsoft releases DeepSpeed, making ZeRO-1 and ZeRO-2 accessible to the PyTorch ecosystem for models >100B parameters. |
| **2020–2021** | **FairScale FSDP (Meta/FAIR)** | Facebook AI Research (FAIR) creates FairScale (open-sourced Oct 2020) and introduces `FullyShardedDataParallel` in early 2021 (Shen Li, Myle Ott, Xian Li, et al.), serving as the prototype testbed before upstreaming into PyTorch core. |
| **Mar 2021** | **ZeRO-3, ZeRO-Offload & ZeRO-Infinity** | DeepSpeed releases **ZeRO-3** (March 2021) alongside **ZeRO-Offload** (offloading optimizer state and compute to CPU host memory) and later **ZeRO-Infinity** (offloading to NVMe SSDs), expanding memory limits beyond physical GPU VRAM. |
| **Jul 2021** | **Meta publicly introduces FSDP** | Meta publishes *"Fully Sharded Data Parallel: faster AI model training with fewer GPUs"*, demonstrating FSDP as a key technology for scaling FAIR's large transformer models without complex layer-rewrite code. |
| **Mar 2022** | **PyTorch 1.11 — Native FSDP prototype** | FSDP enters core PyTorch (`torch.distributed.fsdp`), upstreamed from FairScale. AWS/PyTorch scaling experiments demonstrate feasibility for dense models up to 1T parameters. |
| **Jun 2022** | **PyTorch 1.12 — FSDP Beta & Sharding Enums** | FSDP moves to Beta, formalizing explicit `ShardingStrategy` enums: `FULL_SHARD` (ZeRO-3), `SHARD_GRAD_OP` (ZeRO-2), and `NO_SHARD` (DDP). Introduces `transformer_auto_wrap_policy`, `CPUOffload`, and `FullStateDictConfig`. |
| **Oct 2022** | **PyTorch/XLA FSDP** | Extends FSDP sharding primitives to TPU/XLA environments, demonstrating accelerator-agnostic sharding semantics. |
| **2022–2023** | **ZeRO++** | Microsoft introduces ZeRO++, incorporating block-quantized parameter all-gather (QG-Z3), secondary all-gather (hpZ4), and cross-node communication optimizations for low-bandwidth networks. |
| **Mar 2023** | **PyTorch 2.0 — Production FSDP & HSDP** | PyTorch 2.0 promotes FSDP to production-ready state and adds `HYBRID_SHARD` (HSDP), allowing full sharding intra-node (via NVLink) and replication inter-node (via InfiniBand/EFA). |
| **Apr 2023** | **PyTorch FSDP Paper** | PyTorch team publishes *"PyTorch FSDP: Experiences on Scaling Fully Sharded Data Parallel"* (Yanli Zhao, Shen Li, Rohan Varma, Manish Modadugu, et al., arXiv:2304.11277), documenting architectural co-design across CUDA memory management, dispatcher, and communication primitives. |
| **2023** | **Distributed Checkpointing (`torch.distributed.checkpoint`)** | Introduced to handle sharded model state dictionaries (DCP). Eliminates memory OOMs caused by gathering all parameters to Rank 0 GPU/CPU before saving, and supports re-sharding across different GPU world sizes. |
| **Aug 2024** | **FSDP2 (`fully_shard`) in PyTorch 2.4** | PyTorch rewrites FSDP from scratch. Replaces FSDP1's `FlatParameter` (which flattened sub-module parameters into 1D tensors, breaking parameter identity and breaking `torch.compile` graph capture) with **`DTensor` (DistributedTensor)**. Parameters remain individual tensors sharded along dim 0, enabling 100% native `torch.compile` tracing and clean Tensor Parallelism (TP) composability. |
| **2024** | **FSDP2 + FP8 & Compiler Co-design** | FSDP2 introduces FP8 parameter communication (casting parameters to FP8 before AllGather to halve communication bandwidth) and seamless overlap of collective communication with compiled graph execution. |
| **2024–2025** | **TorchTitan & Multidimensional Parallelism** | Meta releases **TorchTitan**, PyTorch's clean-room reference codebase for LLM pre-training. Demonstrates native 3D/4D parallelism (FSDP2 + TP + PP + CP) built entirely on PyTorch 2.x native primitives. |
| **2025–2026** | **FSDP2 Maturation & FSDP1 Deprecation** | FSDP2 becomes the standard sharding architecture in PyTorch, with FSDP1 deprecated in PyTorch 2.11+. Emphasis shifts to topology-aware dynamic sharding, heterogeneous cluster execution, and unified compiler-managed distributed runtimes. |
